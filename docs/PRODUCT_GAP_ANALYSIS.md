## 1. Existing Capability Classification

| Area | Classification | Notes (Codebase Evidence) |
|---|---|---|
| Core HTTP Server, MySQL Adapter & Schema Auto-Init | **Fully Implemented & Verified** | `server.js`, `src/config/database.js`, `mysqlAdapter.js`, `schema.js` (101 tables initialized cleanly). |
| Auth JWT & Rate Limiting | **Partially Implemented (Security Defects)** | `authMiddleware.js`, `rateLimiter.js` work for standard checks, **but** workspace admins receive `role = 'ADMIN'` causing cross-tenant escalation via `requireAdmin` and `x-workspace-id`. `login()` omits `tenant_id` in JWT payload. |
| Team / Employee RBAC & Tenant Lifecycle | **Partially Implemented** | `tenant_user_memberships` & `adminController.createUser` exist, **but** no tenant-scoped team management endpoints for Workspace Owners (only global `requireAdmin`). |
| Meta Webhook Ingress & Signature Check | **Partially Implemented** | `webhookController.js` queues HMAC-verified webhooks into `system_job_queue` (`META_WEBHOOK_INGEST`), **but** fails to maintain `incoming_webhook_events` table expected by tests, and mixes global fallback tokens for non-tenant-1 accounts. |
| Two-Way Inbox & Conversation State | **Partially Implemented (Risks)** | `webhookService.js` supports soft-delete, read tracking, media proxy (`/uploads/inbound` ownership gate), **but** `botPausedUntil` and `phoneQueues` are in-memory `Map`s (not durable across restarts or multi-worker), and `POST /api/inbox/reply` blocks non-tenant-1 due to unfinished channel-account sender routing. |
| Configurable Conversation Flow Engine | **Implemented with Drift / Regressions** | `conversationFlowEngine.js`, `nodeExecutors/index.js` (30+ node types), `expressionEvaluator.js` (zero-eval), subflow `CALL_SUBFLOW`, Back/Menu/Agent escapes work (`unified_flow_module.test.js` 6/6 pass). **Gaps:** hardcoded resort fallbacks in `webhookService.js`, older flow tests out of sync (`Hotel Green Vally` vs `KonkanTrip`, `BUTTONS` vs `button`), and 1 seeded blueprint fails 20-char Meta button validation. |
| Universal Template Library & Config Engine | **Broken at HTTP Layer** | Core services (`templateInstallService.js`, `templateUpgradeService.js`, `templateConfigValidator.js`) work in direct service tests, **but** `templateController.js` uses `req.user?.tenantId` (undefined) instead of `req.user?.tenant_id`, leaking all API operations to `tenantId = 1`! Also `requireAdmin` allows any tenant admin to publish public master templates. |
| Hospitality Inventory & Double-Booking Guard | **Broken (Data Integrity Defect)** | `room_inventory_daily` lacks a `UNIQUE` index on `(room_type_id, inventory_date)`, so `bulkUpdateInventory` inserts duplicate rows and `checkStayAvailability` oversells closed dates! Universal `catalog_availability_slots` & `catalog_inventory_holds` work properly. |
| Payments & Razorpay Webhooks | **Broken (Security-Critical)** | `payoutController.checkEntityAccess` returns `true` for `!user || user.role === 'ADMIN'`. Razorpay webhook endpoints (`payoutController`, `publicUniversalFulfillmentRoutes`, `billingService`) accept unsigned/`mock_` payloads in production and expose browser `simulatePayment()`. |
| Reports & Analytics | **Partially Implemented (Security Leak)** | `reportsController.js` ignores `tenant_id` and exposes cross-tenant campaigns/deliveries to any `ADMIN` user. `flowAnalyticsService.js` provides real DB-recorded node dropoffs. |
| Task-Scoped AI & Copilot | **Partially Implemented (Industry Bias)** | Grounded RAG (`knowledgeRetrievalService.js`) and deterministic offline fallback work, **but** `taskScopedAiAgentService.js` and `inboxCopilotService.js` hardcode "hotel rooms / resort" copy and lack structured JSON output + prompt injection sanitization when an LLM key is active. |
| SSRF Outbound Webhook Guard | **Partially Implemented** | `webhookExecutor.js` checks IP literal regexes, **but** lacks DNS lookup private-IP check, IPv6 private checks, and redirect blocking (`redirect: 'manual'`). |
| Async Job Queue & Scheduler | **Partially Implemented (TZ Defect)** | `jobQueueService.js` & `jobWorkerEngine.js` use `FOR UPDATE SKIP LOCKED` properly, **but** `schedulerService.js` mixes `NOW()` and `UTC_TIMESTAMP()` on `workflow_scheduled_jobs`, causing timezone skew in `Asia/Kolkata`. |
| Frontend UI / Design System & Duplication | **Duplicated / Incomplete** | `FlowBuilderPage.jsx`, `FlowsPage.jsx`, `FlowStudioPage.jsx`, `AutoReplyBotPage.jsx`, `AutomationPage.jsx`, `AutomationStudio.jsx` overlap; `Sidebar.jsx` & `Topbar.jsx` trigger `frontend_design_system.test.js` failures (legacy emerald hexes, label drift). |
| Billing / Quotas / Entitlements | **Partially Implemented** | Plans (`TRIAL`, `STARTER`, `GROWTH`, `ENTERPRISE`), 18% GST billing (`billingService.js`), and line quota check exist, **but** monthly message quota enforcement during campaign/outbound dispatch and feature entitlement middleware are incomplete. |

## 2. Prioritized Product Gap Analysis Matrix

| Requirement ID | Requirement | Existing Capability | Gap | Business Impact | Priority | Dependencies | Recommended Solution | Acceptance Criteria |
|---|---|---|---|---|---|---|---|---|
| **GAP-L1-01** | Separate Platform Admin vs Tenant Owner vs Employee Roles & Workspace Isolation | `users.role`, `tenants`, `tenant_user_memberships`, `authMiddleware` | Self-registering owners get `role = 'ADMIN'`, bypassing `requireAdmin` and switching to any tenant via `x-workspace-id`. `login()` omits `tenant_id` in JWT. | **Critical:** Complete multi-tenant data breach across all admin/payout/template/user endpoints. | **P0** | None | Introduce explicit `isPlatformAdmin(user)` (`role === 'SUPER_ADMIN'` or `role === 'ADMIN' && original_tenant_id === 1`), assign tenant creators `'USER'` or `'TENANT_ADMIN'` (distinct from platform admin) + `OWNER` in `tenant_user_memberships`, lock `x-workspace-id` strictly to memberships/agency children unless verified Platform Admin, fix `login()` JWT `tenantId`, fix `checkEntityAccess` & `getScopedUserId`. | Negative auth tests verify Tenant B owner gets `403` on `/api/admin/*`, `403` switching to Tenant A via `x-workspace-id`, `403` accessing Tenant A payouts/reports; `security_and_reliability` role-escalation test passes. |
| **GAP-L1-02** | Fix API Tenant Derivation (`req.user.tenant_id`) & Report Isolation | Controllers mostly use `req.user?.tenant_id`; `templateController` & `reportsController` do not | `templateController` uses `req.user?.tenantId` (always `undefined` -> defaults to Tenant 1); `reportsController` filters only by `role !== 'ADMIN'`. | **Critical:** Cross-tenant flow/template/report leak. | **P0** | GAP-L1-01 | Centralize `getAuthTenantId(req)` helper reading `req.user.tenant_id`, update `templateController` and `reportsController` (`campaigns.tenant_id = ?`, `automated_booking_dispatches.tenant_id = ?`). | Tenant A & B calling `/api/v1/template-library`, `/api/v1/template-installations`, `/api/reports/*` remain 100% isolated. |
| **GAP-L1-03** | Tenant-Scoped Team Management, Audit Logging & Upload Isolation | `adminController.createUser` (global only), `audit_logs`, `/uploads/inbound` check | No self-serve Workspace Owner team invite/role endpoint; `/uploads` traversal on `/uploads/inbound/..` returns `401` instead of `403`; uploads not path-scoped cleanly. | **High:** Organizations cannot onboard employees without global admin; security test fails. | **P1** | GAP-L1-01 | Add `/api/v1/workspace/users` (list/invite/update role/status scoped strictly to caller's `tenant_id`, forbidden for `USER` employees); move path traversal & dangerous extension guard before `/uploads/inbound` auth; log membership/security events to `audit_logs`. | Tenant Owner creates/suspends employee in own tenant; cannot touch Tenant B users; employee blocked from owner-only endpoints (`403`); path traversal returns `403`. |
| **GAP-L1-04** | SSRF Defense in Outbound HTTP/Webhook Nodes | `webhookExecutor.validateUrlSecurity` literal IP regex | Bypasses via DNS names resolving to private/loopback/metadata IPs, IPv6 private ranges, numeric IPs, and HTTP redirects. | **High:** SSRF vulnerability allowing tenants to probe internal/cloud services. | **P0** | None | Add async `dns.lookup` verification validating all resolved A/AAAA addresses against RFC1918, loopback, link-local, carrier-grade NAT, and IPv6 ULA; set `redirect: 'manual'` or re-validate redirect hops. | Security unit tests prove localhost aliases, decimal/IPv6 loopback, `169.254.169.254`, and private DNS resolutions are blocked cleanly. |
| **GAP-L1-05** | Payment Webhook Signature Fail-Closed & Checkout Integrity | `payoutController`, `publicUniversalFulfillmentRoutes`, `billingService` Razorpay handlers | Webhooks skip HMAC check if signature is missing, `mock_`, or secret unset; `capture-payment` uses `optionalAuth`; hosted `/pay/:ref` triggers unauthenticated webhook in prod. | **Critical:** Financial fraud — anyone can mark bookings/orders/SaaS plans PAID without paying. | **P0** | None | Fail closed (`401`/`403`) on missing/invalid Razorpay HMAC in `NODE_ENV !== 'test'` (or require explicit signed/sandbox token in test mode); restrict `/orders/:orderNumber/capture-payment` to authenticated owning tenant staff; disable public one-click auto-paid simulation script outside explicit local sandbox flag; escape HTML on 404 receipt page. | Security & payment integration tests verify unsigned/forged Razorpay webhooks return `401`/`403` and do NOT mark orders or plans PAID; valid signed webhook captures payment idempotently. |
| **GAP-L2-01** | Unified Channel Adapter & Tenant Credential Isolation | `metaWhatsAppService`, `webhookController`, `adminController`, `flowService` | Direct `graph.facebook.com` fetches scattered in 3 extra files; `resolveCredentials` falls back to Tenant 1 global token when line token absent; multi-tenant `POST /api/inbox/reply` blocked. | **High:** Cross-tenant credential leakage and broken non-tenant-1 inbox replies. | **P1** | GAP-L1-01 | Route all Graph API URLs through `metaWhatsAppService.getMetaBaseUrl()`; enforce strict tenant-scoped `waba_phone_numbers` lookup for non-tenant-1 accounts (no global Tenant-1 token fallback for Tenant 2+); enable tenant-owned channel reply in `POST /api/inbox/reply` & bot takeover controls. | Tenant 2 replies via its own connected sender line without using Tenant 1 token; Tenant 2 fails closed if it has no line/token; webhook tests mock cleanly. |
| **GAP-L2-02** | Durable Webhook Idempotency, Handoff Persistence & Channel-Scoped Locking | `system_job_queue` (`META_WEBHOOK_INGEST`), `webhookService.js` in-memory Maps | `botPausedUntil` and `phoneQueues` live only in RAM; `webhookController` queues job without writing `incoming_webhook_events` trace (breaking test/audit expectation); outbound auto-replies lack durable outbox. | **High:** In-flight human takeover state lost on server restart; duplicate/crash recovery gaps. | **P1** | GAP-L2-01 | Create `conversation_handoff_states` (or durable column/table keyed by `tenant_id, channel, phone_number_id, contact_phone`) + record idempotent `incoming_webhook_events` + add durable `OUTBOUND_MESSAGE_DISPATCH` outbox job / `whatsapp_messages` pending-to-sent persistence. | Pausing bot for a contact persists across `WebhookService` re-instantiation; duplicate webhook payloads produce zero duplicate inbound rows or duplicate outbound replies. |

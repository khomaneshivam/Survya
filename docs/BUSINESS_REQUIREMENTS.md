# SARVYA — Measurable Business & Technical Requirements

Extracted and evaluated from platform directives, existing PRDs ([TEMPLATE_LIBRARY_PRD.md](TEMPLATE_LIBRARY_PRD.md), [SARVYA_CONNECT_PRD.md](SARVYA_CONNECT_PRD.md)), and security/architecture migration specs ([CONVERSATION_TENANT_SECURITY_ITERATION2.md](CONVERSATION_TENANT_SECURITY_ITERATION2.md), [NO_CODE_WORKFLOW_FOUNDATION_ITERATION4.md](NO_CODE_WORKFLOW_FOUNDATION_ITERATION4.md)).

---

## Evaluated & Prioritized Requirements

| ID | Category | Requirement | Evaluation & Decision |
|---|---|---|---|
| **REQ-SEC-01** | Security / Tenant | Strictly separate Platform Super-Admin vs. Tenant Workspace Admin (`WORKSPACE_ADMIN` / `OWNER`) vs. Employee (`USER`/`AGENT`). | **Must Implement (Critical):** Self-registered workspace owners currently get `role = 'ADMIN'`, granting cross-tenant super-admin and `x-workspace-id` switch privileges. |
| **REQ-SEC-02** | Security / API | Derive `tenant_id` consistently from verified `req.user.tenant_id`; reject cross-tenant access (`403`/`404`) and unauthorized workspace headers. | **Must Implement (Critical):** `templateController.js`, `payoutController.js`, `reportsController.js` have tenant-scope leaks or wrong property casing (`tenantId` vs `tenant_id`). |
| **REQ-SEC-03** | Security / Auth | Support employee/team member onboarding, role assignment within a tenant, password reset/account recovery, and session revocation without allowing cross-tenant escalation. | **Must Implement (High):** Required for Layer 1 multi-user tenant lifecycle (`createWorkspaceUser`, role checks, recovery flow). |
| **REQ-SEC-04** | Security / SSRF | Harden `webhookExecutor.js` and outbound URL connectors against DNS rebinding, IPv6 private/ULA/link-local ranges, octal/hex IPs, and open HTTP redirects. | **Must Implement (Critical):** Prevents internal network/cloud metadata probing via user-configured workflow webhook nodes. |
| **REQ-SEC-05** | Security / Payment | Fail closed on Razorpay webhooks and payment capture unless HMAC-SHA256 signature is verified; block browser-side `simulatePayment()` in non-dev/live mode and require strict signature/token checks. | **Must Implement (Critical):** Currently unauthenticated callers can trigger `/pay/webhook/razorpay` or `/orders/:id/capture-payment` and mark transactions/subscriptions PAID without paying. |
| **REQ-SEC-06** | Security / Media | Enforce path traversal (`..`) `403` defense before auth/static handling and tenant-scoped uploads. | **Must Implement (High):** Ensures uploaded files cannot escape storage root or leak across workspaces. |
| **REQ-COM-01** | Communication | Route WhatsApp sending, receiving, status updates, and media downloads through a unified channel adapter (`metaWhatsAppService`), eliminating hardcoded `graph.facebook.com` fetches across controllers/services and eliminating Tenant 1 global credential fallback for other tenants. | **Must Implement (High):** Prevents accidental credential mixing or live calls bypassing test overrides. |
| **REQ-COM-02** | Communication | Persist durable inbound webhooks (`META_WEBHOOK_INGEST`), maintain `incoming_webhook_events` idempotency, handle out-of-order status callbacks (`READ` never downgraded to `DELIVERED`), and move bot pause/human handoff + per-conversation lock state to durable tenant/channel-scoped MySQL storage rather than in-memory `Map`s. | **Must Implement (High):** Required for multi-line isolation and restart recovery (Journey I). |
| **REQ-COM-03** | Communication | Implement reliable transactional outbound message outbox or durable send job queue (`OUTBOUND_MESSAGE_DISPATCH`) with idempotency keys, retry backoff, and 24h window / opt-out enforcement. | **Must Implement (High):** Guarantees reliable crash recovery and avoids duplicate outbound messages on worker retries. |
| **REQ-WFE-01** | Workflow Engine | Ensure all seeded blueprints pass `validateFlowGraph()` (e.g. Meta 20-char button limits), immutable published versions remain isolated while new drafts iterate, running sessions pin to `flow_version_id`, and `schedulerService` uses consistent `UTC_TIMESTAMP()` queries. | **Must Implement (High):** Currently 1 blueprint fails validation (`21 chars`) and scheduler mixes `NOW()` vs `UTC_TIMESTAMP()`. |
| **REQ-WFE-02** | Workflow Engine | Support node-type capability contracts (input/output schemas, timeout/retry metadata, safe zero-eval conditions, loop guard max hops per turn) and domain-agnostic fallback messaging driven by tenant business profile rather than hardcoded resort strings. | **Must Implement (High):** Required for Layer 3 multi-industry runtime parity. |
| **REQ-TPL-01** | Template Studio | Enforce platform-admin-only `PUBLIC` master template creation/publishing, proper `req.user.tenant_id` scoping on template catalog/installations/upgrades, and controlled non-destructive upgrades preserving tenant config overrides & bindings. | **Must Implement (Critical):** Currently broken by `req.user?.tenantId` typo and open `requireAdmin`. |
| **REQ-BIZ-01** | Commerce / Booking | Fix `room_inventory_daily` missing UNIQUE index (`uq_room_inv_daily (tenant_id, room_type_id, inventory_date)`) so upserts cannot duplicate inventory rows and cause overselling/double bookings; enforce atomic holds across both hospitality rooms and universal slots. | **Must Implement (Critical):** Direct revenue/booking integrity risk (`resort_booking_prd.test.js` confirmed failure). |
| **REQ-AI-01** | AI Assistance | Remove hardcoded hospitality assumptions from `taskScopedAiAgentService` & `inboxCopilotService`, ground strictly in tenant `business_entities`/`ai_knowledge_sources`/`catalog_items`, sanitize prompt-injection markers in untrusted user input, validate structured AI JSON outputs, enforce token/cost caps, and never let AI bypass pricing/availability/payment confirmation. | **Must Implement (High):** Required for Layer 6 multi-industry safety & prompt injection defense. |
| **REQ-ANA-01** | Analytics / Campaigns | Fix tenant scoping on `reportsController.js`; compute funnel, conversion, messaging cost, and AI cost telemetry strictly from recorded DB events with zero fabricated metrics. | **Must Implement (High):** Prevents cross-tenant PII disclosure in reports & exports. |
| **REQ-UI-01** | UI/UX Maturity | Standardize role-gated navigation (Platform Admin vs Workspace Owner vs Employee), clean up legacy gradient/emerald tokens flagged by `frontend_design_system.test.js`, align sidebar labels/routes cleanly, and verify clean `oxlint` + `vite build`. | **Must Implement (Medium):** Completes Layer 8 UI consistency and passes design-system checks. |
| **REQ-OPS-01** | Ops / Billing / SaaS | Enforce tenant plan entitlements & monthly message/WABA line quotas cleanly without breaking existing trials; document safe DB migrations, backup/restore drills, runbooks, and release gates. | **Must Implement (Medium):** Supports Layer 9 & Layer 10 commercial readiness. |

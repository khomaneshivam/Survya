# SURVYA — Conversational Business Studio: Data & Module Architecture (Layer 0)

## 1. Entity-to-Existing-Table Reuse Mapping

| Studio Concept | Primary Existing Table(s) | Additive Studio Extensions (Migrations) | Notes |
| :--- | :--- | :--- | :--- |
| Business Experience Definition | `inapp_experiences` | `studio_mode` (`GUIDED` \| `ADVANCED`), `goal_type`, `goal_config_json`, `published_version_id`, `published_version_number`, `approval_required`, `approval_state`, `initial_reply_config_json` | Existing slug, tenant_id, theme, hours, entity/pipeline links preserved. |
| Experience Version History | `inapp_screens`, `inapp_form_fields` *(mutable draft)* | **`experience_versions`** (`id`, `tenant_id`, `experience_id`, `version_number`, `status`, `snapshot_json`, `validation_report_json`, `changelog`, `approved_by`, `approved_at`, `published_by`, `published_at`, `created_at`) | Mirrors `conversation_flow_versions` immutable snapshot design so active sessions stay pinned to their published version during re-publishing. |
| Conversational Step Components | `inapp_screens`, `inapp_form_fields` | **`experience_steps`** OR typed component blocks inside `inapp_screens.layout_config_json` + formal schema validation via `conversationalComponentRegistry.js` | Screens remain backward compatible while gaining `component_type`, `component_config_json`, `goal_trigger_flag` via clean JSON/schema validation and optional ordered step definitions. |
| Customer Experience Session | `inapp_sessions` | `flow_session_id` *(existing migration)*, `experience_version_id`, `experience_version_number`, `channel_owner` (`WHATSAPP` \| `SURVYA` \| `HUMAN`), `optimistic_lock_version`, `demo_mode`, `goal_status`, `transcript_json` | `optimistic_lock_version` enforces atomic CAS turn updates (`WHERE id = ? AND optimistic_lock_version = ?`). |
| Opaque Continuation Tokens | — | **`experience_continuation_tokens`** (`id`, `tenant_id`, `experience_id`, `flow_session_id`, `inapp_session_id`, `token_hash` UNIQUE, `token_prefix`, `contact_phone`, `channel_source`, `scope`, `is_single_use`, `redeemed_at`, `revoked_at`, `expires_at`, `created_at`) | Never stores plaintext continuation tokens. Enqueued via `system_job_queue` for durable retries & dead-letter recovery. |
| Experience Audit Log | `audit_logs` *(if present)* / `conversation_flow_audit_logs` | **`studio_audit_logs`** (`id`, `tenant_id`, `experience_id`, `version_id`, `actor_id`, `actor_email`, `action`, `details_json`, `created_at`) | Records create, edit, validation, approval, publish, rollback, email retry, and archive events. |

## 2. Backend Module Layout (`src/`)
- `src/services/studio/conversationalComponentRegistry.js` *(Layer 1)* — Authoritative backend component schemas, config validator, and turn input sanitizer/validator covering all 29 conversational UI component types.
- `src/services/studio/continuationTokenService.js` *(Layer 1)* — Cryptographic opaque continuation token creation (`ct_...`), SHA-256 hash lookup, atomic single-use redemption, revocation, expiry check, and scoped customer session issuance.
- `src/services/studio/studioExperienceService.js` *(Layer 2 & Layer 5)* — Mode A guided wizard persistence, Mode B advanced graph/component updates, draft validation, immutable version snapshots, approval workflow, publish, and rollback.
- `src/services/studio/industryBlueprintService.js` *(Layer 3)* — Extends `templateCatalogService` with runnable industry blueprints and isolated `demoMode` session initialization + mock catalog/slot fixtures.
- `src/services/studio/businessGoalService.js` *(Layer 4)* — Evaluates completion criteria and atomically persists idempotent business goal outcomes linked to CRM, bookings, orders, quotes, and analytics.
- `src/services/studio/emailNotificationService.js` *(Layer 4)* — Provider-independent SMTP adapter (`nodemailer` lazy/configurable), unconfigured status reporting, durable `system_job_queue` dispatch, exponential retry, dead-letter handling, secret-free error sanitization, and manual retry endpoint.
- `src/services/studio/studioAnalyticsService.js` *(Layer 6)* — Multi-tenant funnel & goal conversion metrics (`link clicks -> WA replies -> chat launches -> goal completions -> email notifications -> revenue`).
- `src/routes/studioRoutes.js` & `src/controllers/studioController.js` *(Layers 2–6)* — Tenant-scoped Workspace Owner / Studio API surface mounted at `/api/v1/studio`, preserving backward compatibility with `/api/v1/inapp` and `/api/v1/public/x`.

## 3. Frontend Module Layout (`frontend/src/`)
- `frontend/src/components/studio-chat/ConversationalRenderer.jsx` *(Layer 1)* — Shared mobile-first full-screen chat renderer used identically by `/x/:slug`, Studio live preview, and Industry Template `Try Demo`.
- `frontend/src/components/studio-chat/componentRegistry.jsx` *(Layer 1)* — Component renderers for every registered conversational step type.
- `frontend/src/pages/PublicExperiencePage.jsx` *(Layer 1 Refactor)* — Redeems `?ct=` continuation tokens cleanly (stripping sensitive params via `history.replaceState`), persists short-lived customer session token, handles offline/reconnect/expired states, and renders `ConversationalRenderer` without website chrome.
- `frontend/src/pages/SurvyaStudioPage.jsx` *(Layers 2–6)* — Unified Studio hub containing `Overview`, `Industry templates`, `Experiences`, `Experience builder` (`Mode A: Guided Business Setup` & `Mode B: Advanced Experience Builder`), `Chat simulator`, `Published experiences`, `Share links`, and `Execution history`.
